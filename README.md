# ai-toolkit

> **ai-toolkit** is a complete, production-ready suite of AI-agent components for building conversational applications.

一个在命令行里陪你聊天的 AI 助手 Demo。它不只"有问必答"，还做了很多让你聊得更省心、更省钱的努力：

- **记得住你们聊过什么** —— 聊一半关掉程序，下次打开还能接着聊；
- **聊得长了不跑偏** —— 历史太多时自动总结，只把和当前问题最相关的旧对话翻出来；
- **能联网查资料** —— 问它"今天的最新消息"，它会去网上搜；
- **看得见成本** —— 每一轮用了多少 token、花了多少钱，都写进日志，方便你核对；
- **帮你把结论存成文件** —— 说一句"把调研结果保存到 xxx.md"，它会整理好内容、先给你过目，你确认后才写入文件。

## 它能做什么

### 🧠 记住你们的对话（上下文记忆）

- 每次聊天都会自动保存在本地数据库里，并按会话（session）区分。下次启动会自动接回最近一次会话，不用从头说起。
- 你可以用 `/new` 开一个全新的话题，也可以用 `/clear` 把当前话题清空重来。
- 会话多了、每条历史长了，会自动按"最近使用"淘汰最旧的，避免无限膨胀。

### 📏 聊得长也不浪费（自动总结 + 智能回看）

对话变长后，把每个 token 都发给模型既慢又费钱。助手做了两件事来控制成本：

- **自动总结**：当历史条数超过一定量，助手会把较早的对话浓缩成一段"摘要"放进来，而不是把原文全量带上；
- **智能回看**：不会把所有历史都翻出来，而是用"语义相似度"只挑出和你当前问题最相关的几句旧对话。这样既省钱，回答也更聚焦。

### 🌐 联网查资料（可选）

问"今天的最新消息""帮我查一下某公司的近况"这类问题时，助手可以联网搜索再回答。联网功能可在配置里开启或关闭。

### ⚡ 边聊边显示

回答不是等全部生成完才一次性出现，而是**生成一个字显示一个字**，不会有长时间"卡住没反应"的错觉。

### 💰 用量与成本看得见

每一轮对话结束后，会在日志里记录：本次输入/输出 token 数、上下文缓存命中情况（命中越多越省钱）、估算成本。方便你直观地了解每次提问的"开销"。

### 📁 把结果存成文件（保存 + 人工确认）

当你要求"把调研结果保存到文件"时，助手会把内容整理好并暂存，然后在命令行里**把路径和内容预览给你看**，由你确认后才真正写入：

- 输入 `y`：覆盖写入
- 输入 `e`：追加写入
- 输入 `d`：丢弃，不写入

出于安全考虑，只能写到配置的目录内（默认 `outputs/`），绝对路径、`..` 跳转、以及 `.env`、`config.toml`、`*.py` 这类敏感/危险文件都会被拒绝。**任何文件写入都必须经过你的人工确认**，不存在助手自己悄悄写文件的路径。

## 快速开始

### 1. 安装依赖

```bash
pip install -e .
```

如果想用真正的"语义"来挑历史对话（更准），再装语义模型（可选，不装也能跑，会退回简化方案）：

```bash
pip install -e ".[embeddings]"
```

### 2. 配置模型

复制或编辑项目根目录的 [`config.toml`](config.toml)，填入你使用的模型服务信息（模型名、接口地址、密钥）。参考模板见 [`conf/config.toml`](conf/config.toml)。

### 3. 启动聊天

```bash
python src/demo/ai_chat.py
```

常用参数：

| 参数 | 说明 |
|------|------|
| `-c, --config <文件>` | 指定配置文件（默认 `config.toml`） |
| `--clear-cache` | 启动时清空所有已保存的对话记录 |

### 4. 命令行里的常用操作

| 你输入 | 作用 |
|--------|------|
| `q` / `quit` / `exit` | 退出 |
| `clear` | 清空上箭头输入历史 |
| `/session` | 查看当前会话 id |
| `/sessions` | 列出所有会话（编号、消息数、最近更新、首句预览） |
| `/use <序号或id前缀>` | 切换到指定会话（`/switch` 同义） |
| `/delete <序号或id前缀>` | 删除指定会话 |
| `/clear` | 清空当前会话的记忆，并开启新会话 |
| `/new` | 开启一个全新的会话 |

当你让它"保存到文件"后，按提示输入 `y` / `e` / `d` 决定是否写入、如何写入。

## 配置说明（`config.toml`）

下面用大白话解释每个配置段的作用，示例见 [`config.toml`](config.toml) 与 [`conf/config.toml`](conf/config.toml)。

### `[llm]` —— 模型服务
| 键 | 含义 |
|----|------|
| `model` | 使用的模型名 |
| `base_url` | 模型服务接口地址 |
| `api_key` | 密钥 |
| `temperature` | 回答的"发挥程度"，越大越随机发散，越小越严谨稳定 |

### `[agent]` —— 助手行为
| 键 | 含义 |
|----|------|
| `system_prompt` | 给助手的角色/行为设定 |
| `max_iterations` | 单轮最多思考/调用几次（防止死循环） |
| `max_execution_time` | 单轮最长耗时（秒） |
| `debug` | 是否输出内部调试信息 |

### `[context.cache]` —— 对话记忆
| 键 | 含义 |
|----|------|
| `enable` | 是否开启记忆 |
| `backend` | 记忆存哪：`sqlite`（本地数据库，重启可恢复）/ `memory`（仅本次运行） |
| `path` | 数据库文件路径 |
| `max_sessions` | 最多保留多少个会话，超出按最旧淘汰 |
| `max_messages_per_session` | 单个会话最多存多少条，超出按最旧淘汰 |
| `max_context_messages` | 每次实际带给模型的上下文条数上限 |
| `trim_strategy` | 历史太多时的策略：`sliding_window`（只留最近若干条）/ `summarize`（总结成摘要） |
| `recent_window_size` | 总结模式下保留的最近原始消息条数 |
| `summary_trigger_messages` | 历史超过多少条时触发总结 |

### `[context.rag]` —— 智能回看
| 键 | 含义 |
|----|------|
| `enable` | 是否按"语义相似"挑选相关历史 |
| `backend` | 向量检索实现（默认 `sqlite_vec`） |
| `embed_model` | 语义模型 |
| `top_k` | 每次最多挑几条相关历史 |
| `min_relevance` | 相关度门槛，低于此值的旧对话不带上（避免硬塞不相关的内容） |
| `recent_boost` | 越近的对话加权越高（可选项） |

### `[search]` —— 联网搜索
| 键 | 含义 |
|----|------|
| `enable` | 是否开启联网搜索 |
| `provider` | 搜索引擎（当前支持 `duckduckgo`） |
| `max_results` | 每次最多返回几条结果 |

### `[log]` —— 日志
| 键 | 含义 |
|----|------|
| `level` | 日志级别：`DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `path` | 日志文件路径；留空则只打印到控制台 |

### `[tools.save_file]` —— 保存文件
| 键 | 含义 |
|----|------|
| `base_dir` | 允许写入的目录（默认 `outputs`）。保存功能默认开启且**每次写入都需人工确认**，没有大小限制。 |

## 目录结构

```
src/
  demo/ai_chat.py         # 程序入口：加载配置、启动命令行聊天
  config/config.py        # 配置定义与解析
  component/
    agent_service.py      # 助手服务：组装模型/记忆/搜索，处理每轮对话
    context_manager.py    # 对话记忆的调度：总结、智能回看、组装上下文
    context_store.py      # 记忆存储的接口（SQLite / 内存）
    sqlite_store.py       # SQLite 记忆存储
    memory_store.py       # 内存记忆存储
    rag_index.py          # 智能回看（向量检索）接口
    rag_sqlite_vec.py     # 基于 SQLite 的向量检索实现
    summarizer.py         # 把长对话总结成摘要
    embeddings.py         # 文本转向量（语义）
    search_tool.py        # 联网搜索
    file_tool.py          # 保存文件（含安全校验与人工确认）
    token_usage.py        # token 用量统计与成本估算
    logger.py             # 统一日志
    cli.py                # 命令行交互界面
sql/create_table.sql      # 数据库表结构
data/                     # 对话记录数据库（运行时生成）
logs/                     # 运行日志（运行时生成）
```

## 说明

- 对话记录保存在 `data/context_cache.db`（SQLite 单文件），删除该文件即可彻底清空记忆。
- 用量与成本记录在日志中（如 `logs/app.log`），不写入数据库。
- 本 Demo 主要用于学习与实验；联网搜索依赖第三方服务，网络波动时可能返回"暂不可用"提示，属正常现象。
